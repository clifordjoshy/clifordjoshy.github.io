Minesweep.rs - a no guess Minesweeper

an implementation of Minesweeper that guarantees that boards are solvable without having to guess

uses rust, egui, wasm
 November 21, 2026 

Links

 GitHub    Demo    Simon Tatham's Blog

About

The original version of Minesweeper in Windows XP does not guarantee that every board is solvable, meaning you can end up in a situation where you have to make a random guess to proceed. This implementation aims to generate boards that can be solved using logical deductions alone, inspired by Simon Tatham’s implementation of the same idea. While I referred to his excellent blog for guidance, the implementation is my own.

We achieve this by running a solver that applies the same deductions a human player would. Whenever the solver gets stuck, we run a “perturber” that moves one or more mines around, allowing the solver to make at least one new deduction. We repeat this process until the board is guaranteed to be solvable. I’ve gone into more detail about the approach in the accompanying post.

Solving a Minesweeper board is NP-complete (Kaye, 2000). However, for the standard board sizes (and quite a bit more), we can run the perturb-solve loop fast enough that it’s basically unnoticeable. We can of course only do this after the first click, since the start position decides the state of the board.

Some quick benchmarks on time taken to build a solvable board, sampled across a 1000 random boards per difficulty.

Personal Notes

This was my first experience with Rust, and I’ve got to say, I can see the appeal. All the syntactic sugar and the general functional programming paradigms when working with iterators are quite nice. On the project, this has been on my to-do list for the longest time, and I’m glad I finally have my very own solvable Minesweeper!

Another benefit of building it in Rust is that it’s pretty straightforward to compile it into WASM. The WebAssembly build of minesweep.rs is available at /demos/minesweeper, and in the iframe below.
